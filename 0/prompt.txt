<pasted_content id="c7fc">
How did we solve now the Tags which the agent is showing? Is this reasoning traces some times now?

No, the tags never show the model’s reasoning. They’re built entirely from the agent’s MCP calls.

Main line: the UI turns each tool call into words, in describe() in AgentCursor.tsx. For example, order(site="storeB", qty=75) becomes “Order 75 · Store B”, advance() becomes “Next week”, and observe() becomes “Checking the state”. Verb and site names come from the data-label on the dock buttons and the map labels.
Second line (“Testing: …”): the last text the agent sent with its note() tool. That’s the closest thing to reasoning, but it’s what the agent chose to write down, not its internal thinking.
Not shown: Gemini’s thinking and its text between tool calls never leave the harness. Showing those would need the harness to forward them as events.

but I saw something like "lets explore each stores plan first to uncover hidden things" is this also deterministic and not from the LLM?

That sentence comes from the LLM. It isn’t deterministic.

The agent can call the MCP tool note(text) to write down the hypothesis it’s testing. Gemini writes that text itself, for example “Let’s explore each store first to uncover hidden things”.
The UI shows the latest note in two places:
the second line of the cursor tag, “Testing: …” (cut to about 70 characters)
“Now testing” in the Agent panel

So the tag has two lines:

Line	Source
“Order 75 · Store B”	built from the tool call, deterministic
“Testing: …”	the agent’s own words from note(), from the LLM

It’s still not Gemini’s hidden thinking. It’s only what the agent decides to write down with note(), so it’s a voluntary reasoning trace that appears only when the agent calls that tool.

so we could say notes would trigger a voice as well right?

Yes, that would work well, but notes don’t trigger a voice yet.

Cheap: a note is already ready-to-read text, so it only needs Gradium, not Gemini. You’d get one short audio clip per note, with no rewriting.
Fits the existing pieces: the UI already receives every note() live through the event stream (that’s how “Testing: …” appears). The narration endpoint would get a third kind, for example kind: "note" with the text, and the narrator pill would play it.
Throttle: in our runs the agent wrote only a few notes per episode, so it’s fine. To be safe, read only the newest one and skip it if a voice is already playing or the narrator is muted.
Delay: a few seconds for Gradium to generate it, so the voice comes slightly after the cursor tag.
Distinguish the voices: the agent’s notes could use a different Gradium voice than the narrator. Then you hear “the agent thinking” versus “the narrator explaining”.
